## 子代理支持
- **归属**：AI代理技能操作 / 子代理调度与管理

**摘要**（可编辑）
启用多代理/子代理支持功能，在Codex中通过配置multi_agent=true，在Gemini CLI中通过invoke_agent工具调度。

**详述**（可编辑）
子代理支持在不同平台有不同实现：在 Codex 中，通过在配置文件 ~/.codex/config.toml 的 [features] 段设置 multi_agent = true 来启用多代理支持，激活 spawn_agent、wait_agent 和 close_agent 工具，这些工具用于实现并行代理调度和子代理驱动开发等技能。在子代理驱动开发中，审查子代理在返回审查结果后应立即关闭；实现子代理则需保持打开状态直至其任务审查通过，因为修复循环会恢复该实现子代理，完成后再关闭。若无法向已生成的代理发送后续消息，则每个修复轮次都应作为一个携带摘要、报告文件和发现的新实现子代理进行调度。在 Gemini CLI 中，通过 invoke_agent 工具调度子代理，该工具接受 agent_name 和 prompt 参数；也可通过聊天语法快捷方式 @agent_name 调用，内置代理名包括 generalist、cli_help、codebase_investigator 以及在启用浏览器工具时的 browser_agent。技能可通过 'Subagent (general-purpose):' 形式调度，引用提示模板文件或提供内联提示。
